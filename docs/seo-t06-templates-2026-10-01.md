# T06 — шаблоны услуг и статей

Дата: 01.10.2026. Пилот принят владельцем ответом «продолжай» после показа и вопроса о публикации. Выпущен коммит `788d3699`; 15 production HTTP-проверок прошли.

## Что готово

- Отдельный контракт услуг: `lib/mediaMarketing/serviceContent.ts`. Пилот `sbornye-gruzy` — **draft**, с фактами T04, датой проверки и сроком актуальности. Услуги не маскируются под блоговые статьи.
- HTML услуги: прямой ответ, направления, способы передачи, параметры расчёта, процесс, FAQ, дата проверки, переход к калькулятору и настоящие ссылки. Работает без JavaScript.
- Публичный обработчик `/api/public-service-page?slug=...` и маршрут Nginx `/uslugi/<slug>`. Черновики, неизвестные и просроченные записи возвращают 404. `?preview=true` не открывает черновики. Публичного режима обхода нет.
- Sitemap добавляет только услуги с утверждением и действующим сроком; дата проверяется при запросе по Москве. Это не замена полной проверке источников T07/T08.
- Статья `/blog/<slug>`: краткий ответ из описания, оглавление по заголовкам, дата реальной публикации при наличии, ссылка на расчёт, Article-разметка. Автор не выдуман: в текущей CMS поле проверенного автора отсутствует, его ввод относится к T07. Нельзя обозначать издателя как проверившего эксперта.
- Для опубликованной услуги разметка Service содержит только видимые название/описание и HAULZ. Без цен, рейтингов, отзывов и неподтверждённых обещаний. Превью noindex, без разметки опубликованного материала и аналитики.
- Зарегистрирован только точный аналитический путь `/uslugi/sbornye-gruzy`; параметры заявки исключаются, произвольные названия услуг не отслеживаются.

## Типы контента и границы

| Тип | URL | Основа и обязательные данные |
|---|---|---|
| Услуга | `/uslugi/<slug>` | Реестр услуг, ответ на задачу клиента, условия, маршрут, FAQ, CTA, подтверждение и дата проверки |
| Инструкция | `/blog/<slug>` | Конкретный вопрос, короткий ответ, шаги, источники требований, автор/эксперт после появления подтверждённых данных |
| Кейс | `/blog/<slug>` | Фактический результат и разрешение клиента; нет данных — нет публикации |
| Новость | `/blog/<slug>` | Дата события, первичный источник, объяснение применимости; не выдавать новость за постоянные условия услуги |

Новые поля автора, первоисточников и типа статьи, версии и обязательная редакционная проверка CMS — T07. Автогенерация и автоматическая публикация не включены. Существующие статьи остаются совместимыми; шаблон не превращает их описание в независимо проверенный факт.

## Предпросмотр

Команда `node --import tsx scripts/preview-content-templates.ts` создаёт `/tmp/haulz-t06-preview/service.html` и `article.html`. Можно передать другой каталог аргументом. Превью статические, без внешних скриптов; ссылки на существующие разделы ведут на haulz.space. Пример статьи — «Что подготовить для расчёта перевозки», не юридическая инструкция. Статья о документах из T05 всё ещё требует источников и экспертной проверки.

Для просмотра запущен локальный HTTP-сервер `127.0.0.1:9046`. Это временный предпросмотр, не публикация на haulz.space.

## Приёмка и выпуск

По утверждённому владельцем T04: «До приёмки пилота — только черновики». Показан конкретный пилот услуги, а не запрос абстрактного разрешения. После приёмки владельцем записать дату утверждения, проверить актуальность фактов и выпустить код и выбранный материал. Затем проверить `/uslugi/sbornye-gruzy`, unknown/draft 404, sitemap, canonical, HTML без JS и переходы к калькулятору; только после этого закрыть T06.

Не выполнять полный sync/reset API VPS: в `/opt/haulz/app` имеются изменения других задач. Изменённые импортируемые модули могут быть закешированы работающим Node-процессом; простое копирование файлов не доказывает обновление шаблона. Выпуск API требует отдельного контролируемого плана без потери этих изменений.
