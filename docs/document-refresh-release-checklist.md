SSH с текущего компьютера на оба VPS отклонён (Permission denied). Пользователь выполняет серверные команды самостоятельно. Серверная проверка не заменяется локальными тестами.

## Команды на каждом VPS

```bash
cd /opt/haulz/app
 git fetch origin main && git merge --ff-only origin/main
```
Если Git сообщает о пересечении локальных изменений — остановиться, ничего не сбрасывать.

Диагностика на backend-VPS (72.56.36.185), без запросов в 1С:

```bash
cd /opt/haulz/app
(
  set -e
  set -a
  source /opt/haulz/.env
  set +a
  node --import tsx scripts/check-document-refresh.ts
)
```
Если отсутствует cron_work_state или one_c_request_gate/one_c_request_waiters, применить существующую миграцию 116 к общей БД. Не применять повторно без необходимости; скрипт проверяет наличие таблиц.

```bash
systemctl restart haulz-api
curl -fsS --retry 10 --retry-connrefused --retry-delay 2 --max-time 5 http://127.0.0.1:3000/health
```

На cron-VPS (194.87.140.125), после обновления кода:

```bash
cd /opt/haulz/app
systemctl restart haulz-cron
curl -fsS --retry 10 --retry-connrefused --retry-delay 2 --max-time 5 http://127.0.0.1:3000/health
python3 deploy/install-document-queues.py
crontab -l
```
Установщик сохраняет резервную копию и заменяет только refresh-cache, остальные задания сохраняет. Часовой пояс ОС — Europe/Moscow; оба VPS должны использовать одну БД. Службы исполняют TypeScript через tsx, отдельная сборка бэкенда не требуется; зависимости не менялись.

Ручная проверка новых очередей (на cron-VPS):

```bash
/opt/haulz/cron-call.sh '/api/cron/refresh-cache?kind=invoices&lane=recent'
/opt/haulz/cron-call.sh '/api/cron/refresh-cache?kind=perevozki&lane=active'
tail -n 20 /var/log/haulz-cron-call.log
```
Ответ skipped/not_due_or_running допустим, если задание уже запускалось. Это не подтверждение новой загрузки. Проверять завершённые результаты и ошибки.

Для фронтенда проверить успешное развёртывание после push. Git push сам по себе не подтверждает публикацию сайта. Суммы и статусы проверяются только после обновления обеих частей.

Локальная проверка: 80 тестов; TypeScript фронтенда и бэкенда; production-сборка; проверка установщика cron с сохранением посторонних заданий.
