# Материалы UX-аудита

База: `main@b192f409`. Проверки: 18–19.09.2026. Данные синтетические.

## Стенд

Реальные компоненты HAULZ собраны во временной рабочей копии вне исходников приложения. Обёртки AppShellProvider, AppRuntimeProvider, SWRConfig и `.profile-saas-shell`; стили приложения подключены. Полный header/AppTabBar отсутствует.

HTTP-ответы подменены; внешние подключения заблокированы CSP. Запись суммы меняет только массив в памяти. Остальные записи запрещены. Никакие счета, заявки и сообщения не отправлялись в production/1С. Секреты не использовались.

Fixtures: шесть заборов разных статусов, один начатый маршрут, три строки счетов (1000, 2000 и пустая сумма), вымышленные компании и контакты. Остальные API в основном возвращают пустые массивы. Поэтому проход рендера не доказывает правильность наполненного журнала или всех прав.

## Файлы

- `responsive-checks.json`: 78 наблюдений, 13 экранов × 390/768/1440 × light/dark. `fixtureError=false` относится к границе стенда, не к отсутствию всех ошибок приложения. `smallTargets` — грубое число элементов меньше внутренней цели, не автоматический вердикт WCAG.
- `*-light|dark-390|1440.png`: 16 снимков dispatch, driver, billing, documents. Снимки documents показывают исходный раздел, а не все вкладки. 768 проверен измерениями, без отдельного набора PNG.
- `billing-evidence.json`: две суммы менялись на 1111 и 2222; после сохранения первой вторая вновь 2000. Здесь же computed colors заголовка dark.
- `drawer-unsaved.json`: в карточке введено 009999, после закрытия/открытия вновь 000001.
- `order-draft.json`: после «Назад к заявкам» и нового открытия формы введённый номер отсутствует.
- `profile-keyboard.json`: карточки профиля — DIV без роли/tabIndex; в основном меню стенда нет фокусируемых элементов.
- `error-states.json`: видимый текст при 503. Запись documents здесь относится к открытой форме, не журналу.
- `orders-journal-error.json`: отдельная проверка именно журнала заявок после закрытия формы; он корректно показывает ошибку.
- `findings.json`: машинно читаемый реестр, соответствует `../ux-audit.md`; это результаты аудита, не автоматические тесты.

## Повторение наблюдений

1. Подключить перечисленные реальные компоненты к mock API, не к production.
2. Для billing изменить две строки и сохранить первую; сравнить поля обеих строк.
3. Для dispatch открыть сданную карточку, изменить номер без сохранения, закрыть и открыть.
4. Для documents открыть новую заявку, заполнить номер, вернуться в журнал и открыть снова.
5. Для error-state вернуть 503 при пустом кэше и сравнить сообщения со сценариями 200/empty и 200/data.
6. Для dark измерить вычисленные цвета th. #e5e7eb на #f8fafc даёт контраст около 1.18:1 по относительной яркости sRGB.
7. Для профиля проверить DOM/AX и пройти меню клавиатурой в полном App.

Изолированный fixture не включён в код продукта и не оставляет работающего сервера по завершении аудита. Для долговременной автоматизации использовать TECH-03 с контролируемыми fixtures. Native, экранная клавиатура, screen reader, реальные роли, сеть/GPS, конкурентные записи и 1С остаются отдельными проверками.
