# Действия водителя без подтверждения сервера

Актуально: 19 сентября 2026. UXA-21 — частично реализован, требуется полевой тест.

| Состояние | Что доступно | Что ждёт синхронизации |
| --- | --- | --- |
| Нет ожидающих команд | Действия текущей точки по серверному статусу | — |
| Сохранено прибытие точки A, версия совпадает | Забор с фото или проблема точки A; затем независимая точка B | Команда результата A отправится строго после прибытия |
| Сохранена команда маршрута | Просмотр и синхронизация | Действия точек, зависящие от состояния маршрута |
| Есть ожидающие команды | Просмотр очереди и повторная отправка с тем же requestId | Изменение порядка остановок |
| Конфликт версии одной точки | Отправка команд независимых точек | Эта точка и следующие команды с тем же id |
| Нет сети / 5xx / ошибка авторизации | Сохранённые отметки остаются на устройстве | Отправка очереди прекращается |
| Смена аккаунта / выход из экрана во время отправки | Результат уже начатой команды сохраняется в очередь её владельца | Новые команды старой сессии не отправляются |

Локальная отметка прибытия открывает форму забора, но не меняет сохранённый серверный снимок и подтверждённый прогресс. Результат сохраняется в очередь с версией прибытия + 1 и собственным requestId; напрямую в API до прибытия не отправляется. Фото хранятся в команде. При конфликте обе команды остаются в очереди. Сдача всего маршрута на склад требует синхронизации всех заборов; полный цикл «прибыл → забрал → сдал» без сети пока не поддерживается.

## Приёмка на устройстве

1. Войти водителем, открыть маршрут с двумя точками.
2. Отключить связь, добавить отметку с фото на точке A; проверить уведомление о локальном сохранении.
3. После локального прибытия A заполнить места и фото, завершить забор без сети. Проверить две команды A с разными requestId. Открыть независимую точку B; убедиться, что команды A её не блокируют.
4. Перезапустить приложение; проверить сохранность очереди и фото.
5. Восстановить связь, синхронизировать; проверить статусы сервера и отсутствие дублей.
6. Повторить с изменением точки диспетчером: конфликт A не должен уничтожать фото или блокировать независимую B.
7. Во время задержанного ответа сменить аккаунт: очередь A не показывается пользователю B, следующие команды A не отправляются.

Локально проверены остановка по смене сессии, сохранение requestId/фото, конфликт и независимые точки. Реальная камера, IndexedDB после перезапуска ОС и нестабильная мобильная сеть требуют отдельной приёмки.

Этап 10: 26 тестов очереди/черновиков/мобильного сценария прошли. Дополнительный тест API на PGlite подтверждает повторную доставку обеих команд: версия растёт ровно на 2, фото сохраняется один раз. Это локальная интеграция с БД, не тест реальной мобильной сети.
