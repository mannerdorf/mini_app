## Контракт

- `media_content_plans` — рабочий текст. Каждое сохранение создаёт новую числовую ревизию и снимок в `media_content_revisions` с автором изменения.
- `media_site_publications` — отдельно выбранный опубликованный снимок. Редактирование, регенерация и восстановление черновика его не изменяют.
- `media_published_site_content` — единый источник чтения для нового публичного HTML статьи, списка, JSON API и sitemap. TG-only и неопубликованные рабочие версии сюда не попадают.
- Публикация требует сохранённую текущую ревизию, сайт среди каналов, допустимый уникальный slug, заголовок, описание, текст, автора, описание источников/проверки и явное подтверждение редактора.
- CAS по номеру ревизии и блокировка строки предотвращают перезапись чужих правок, включая запоздавшую генерацию. Конфликт — 409, неполная редакционная проверка — 422. Адрес живой статьи закреплён: его изменение требует отдельного плана редиректа.
- Восстановление создаёт новую рабочую ревизию. Чтобы вернуть прежний текст на сайт, редактор проверяет и публикует эту восстановленную ревизию.
- Старые закешированные обработчики не могут обойти новый порядок обновления/публикации: SQL-триггер отклоняет записи без контекста редактора и статус `published`. Старые вкладки нужно обновить. Удаление истории/материалов с версиями намеренно не доступно через новый редактор; история сохраняется.

## Интерфейс

Админка → Медиаплан → выбрать материал. Поля заголовка, адреса, описания, текста, автора, источников, анонсов и каналов. Сохранение черновика; предпросмотр без исполнения скриптов; опубликованные и рабочие поля рядом; чек-бокс проверки текущей сохранённой ревизии; отдельная публикация; список истории и восстановление. Несохранённый текст нельзя опубликовать или перегенерировать. Статус сайта показан независимо от статуса рабочего текста.

Выбор Telegram/email/других каналов означает подготовку, **не доставку**. Доказательства фактической отправки и интеграции каналов относятся к T12 и последующим этапам. В текущем редакторе нет кнопки, имитирующей успешную отправку.

## Сервер и выпуск

Добавлены новые обработчики `admin-content-editor`, `admin-content-setup`, `public-editor-article`, `public-editor-index`, `public-editor-blog`, `public-editor-sitemap` и новые модули чтения. `admin-content-setup` принимает только фиксированную миграцию из репозитория и требует admin token; SQL/пути от клиента не принимает. При ошибке транзакция откатывается. Исходные API и чужие изменения VPS не переписывались; процесс не перезапускался. Nginx фронтенда направляет блог, его JSON и sitemap к новым обработчикам.

Ссылки внешних источников не загружаются автоматически, содержимое source_notes не включается в публичный API. Заполненное поле источников не является автоматической проверкой достоверности — источники/факты, очередь и бюджет генерации относятся к T08. Автор показывается только из заполненного поля, не придумывается автоматически. Сервисный пилот T06 продолжает работать отдельно.
