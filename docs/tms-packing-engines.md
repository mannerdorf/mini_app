# TMS: сравнение методов укладки

Вкладки LAFF, LoadZa и «Текущий» используют одну выборку и общие ограничения.
Результаты сохраняются отдельно до изменения груза или параметров. Повторный
расчёт меняет только текущую вкладку. В таблице сравнения — объём, масса,
число целых перевозок/мест и время расчёта. Расчёт выполняется в Web Worker.

## Происхождение

Это браузерные **адаптации алгоритмов**, а не запуск Java/Python пакетов.
Не следует представлять вкладки как неизменённые upstream-программы или
приписывать им опубликованные upstream-проценты заполнения.

- LAFF: https://github.com/skjolber/3d-bin-container-packing,
  commit `0206e88f7c394ae58a8e6469b0f4494a1294b718`, Apache-2.0.
  Крупное основание начинает ярус, затем подбираются места на оставшуюся
  высоту и заполняются трёхмерные остаточные пространства. Для браузерной
  реализации используются максимальные свободные параллелепипеды; перебор
  всех перестановок Java-пакета не переносился. Сравниваются сортировка по
  основанию и сортировка по плотности с тем же ярусным алгоритмом.
  При проверке опоры сохраняются свободные поверхности ниже границы яруса:
  иначе низкие коробки создавали бы недоступные пустоты. В варианте по плотности
  высота яруса расширяется для более высокого места, стоящего на его основании.
- LoadZa: https://github.com/HamzaMrA/LoadZa,
  commit `2b9f0c34570d5fdd67172e4147bdf4658a86d5d4`, MIT,
  `core/solver_ep.py`, `core/extreme_points.py`, `core/improve_sa.py`.
  Перенесены угловые точки, гравитационная осадка, варианты layer/dbl/contact,
  распределение веса по площади контакта и перенос нагрузки через цепочку
  опор. Для атомарного отбора перевозок используется ограниченный поиск
  последовательности с продвижением непоместившихся мест. Полный simulated
  annealing, балансировка центра масс и multistop не перенесены.
  Для быстрого поиска опор и столкновений добавлен индекс соседей по основанию
  XY с сохранением всех высот (upstream использует трёхмерный spatial index).
  FIFO/LIFO здесь означает очередь отбора по приёмке, не порядок выгрузки.

Тексты лицензий: `third_party/tms/LAFF-LICENSE.txt`,
`third_party/tms/LoadZa-LICENSE.txt`. Авторские уведомления сохранены.

## Общие правила

- Целые перевозки; при строгом отборе — остановка на первой неподходящей.
- Приоритеты влияют на отбор, а не создают физические зоны заказчиков.
- Полная опора 100%, без пересечений и выхода за границы кузова.
- Все нижние опоры несут накопленную нагрузку всех верхних мест.
- Плотность верхнего места не превышает плотность его опор.
- Палета по полу остаётся на полу. Палета на палету — только при разрешении
  для верхней и каждой нижней палеты. Коробки над палетами разрешены с
  соблюдением опоры и нагрузки.
- Нагрузка задаётся `maxTopLoad`; собственный вес не является дополнительным
  потолком в адаптациях. В режиме оценки множитель применяется к массе места.
- Независимая проверка окончательного плана восстанавливает опору и нагрузку
  по геометрии, а не доверяет метаданным алгоритма.

## Обезличивание и реальные размеры

Перед отправкой в Worker перевозки/заказчики/маршруты заменяются условными
идентификаторами; имена, получатели, номера и бизнес-идентификаторы остаются
в интерфейсе. Все методы получают одинаковую модель. Результат сопоставляется
с оригиналами только после расчёта. Внешние API не используются.

Если размеров нет, объём и масса равномерно распределяются по местам.
Размеры рассчитываются из объёма с учётом ширины/высоты кузова. Палеты
оцениваются по выбранному основанию и числу палет. Это предварительные формы,
а не фактическая геометрия груза или измеренная прочность упаковки.

`PlanOptions.packages[cargoId]` уже принимает группы с `count`, `length`,
`width`, `height`, `weight` (метры/кг), правилами штабелирования и поворота.
Для уникальных мест передаются группы `count: 1`. Явные размеры заменяют
оценку в каждом из методов. Суммарный вес сверяется с перевозкой.

Критерий сравнения: максимальный найденный объём после соблюдения приоритетов,
при одинаковой выборке, резерве и физических правилах. Оптимальность не
гарантируется. Введённые пользователем параметры упаковки важнее визуальной
полноты. Проценты из тестов разных проектов нельзя сравнивать без одинаковых
исходных форм и ограничений.
