# Этап 10: локальные исправления, порядок выпуска

## Общие лимиты запросов (SEC-09)

Перед выкладкой API применить `migrations/111_shared_rate_limits.sql` к общей PostgreSQL базе всех воркеров. Таблица не содержит исходных IP или логинов: ключи хешируются SHA-256. Лимит на 60 секунд обновляется атомарным UPSERT. За один запрос очищается не более 20 старых записей; остальные убираются постепенно.

Задать `TRUSTED_PROXY_IPS` только для фактических адресов непосредственных доверенных прокси. В VPS-конфигурации это может быть loopback Nginx, но адрес нужно сверить с конфигурацией хостинга. Без настройки используется socket peer; заголовки от произвольного клиента игнорируются. Нельзя указывать произвольные внешние адреса или доверять всем прокси. Проверить, что прокси формирует корректную цепочку X-Forwarded-For. На платформе без socket peer клиенты попадают в общий `unknown` bucket: до выпуска требуется адаптер с документированной гарантией доверенного заголовка платформы.

При недоступной БД/таблице защита закрывает запросы с 429. Поэтому **сначала миграция и proxy-конфигурация, затем код**. Миграция обратно совместима со старой версией приложения. При откате кода таблицу можно оставить. Здесь рабочая база и окружение не изменялись.

## Маршруты

- Структурные изменения сохраняют эксклюзивную блокировку; выполнение независимых рейсов использует общую входную блокировку и отдельный ключ маршрута. Запуск дополнительно блокирует водителя и машину, повтор команды — actor/requestId. Производительность нескольких реальных PostgreSQL-соединений отдельно не измерялась.
- Для текущего и предложенного порядка пересчитываются участки на прогнозное время выезда, включая ожидание и погрузку. Не более 42 дополнительных запросов при 20 остановках и двух вариантах. Сохраняется общий таймаут провайдера 85 секунд. Участки дальше 15 минут используют статистику; расчёт не гарантирует глобально оптимальный порядок. Линии карты пока строятся на время старта — интерфейс это сообщает.
- Город водителя: сохранённый ручной выбор по аккаунту; иначе город справочника с приоритетом опубликованного/начатого рейса на сегодня. Дата считается в часовом поясе выбранного города. При нескольких равных вариантах используется последняя обновлённая карточка, город можно изменить вручную.
- Конфликтные офлайн-команды остаются с фотографиями; независимые точки отправляются. Повтор с новой версией требует явного согласия и получает новый requestId. При неизвестном сетевом результате идентификатор остаётся прежним.

## UI и проверки

- Wildberries использует общий загрузчик документов и Filesystem/Share для Capacitor. Контракт проверен с подменёнными native API; физические Android/iOS ещё нужно проверить.
- Модальные формы используют native dialog, доступное имя, цикл Tab, Escape, возврат фокуса и подтверждение потери ввода. Проверять также экранную клавиатуру и системную кнопку «Назад» на устройствах.
- Финансовые кнопки: зона 44 px, второстепенные операции в «Ещё», удаление отделено, общие токены светлой/тёмной темы. Контраст текста проверен отдельно, цвет не заменяет подпись.
- `npm run test:e2e:guest` автоматически поднимает Vite. Незапущенный сервер больше не превращает проверки в пропуски.
- Workflow `Checks` запускает unit/API, серверный TypeScript, build и мобильный guest smoke. Для обязательного merge gate администратор должен включить `Checks / local-contracts` в защите ветки. Это настройка GitHub; локальный файл её не меняет.
- Локальный Playwright Chromium установлен, но macOS sandbox запрещает bootstrap/MachPort запуска. Полный E2E-проход остаётся неподтверждённым. Встроенный браузер использован для ограниченной проверки реальных компонентов на изолированной тестовой странице.

Никаких production API, реальных 1С/2ГИС, ключей из env, commit/push/deploy в этом этапе не использовано.
