# Песочница заявок

В Документы → Заявки раскрыть «Песочница · путь загрузки заявок» и нажать
«Проверить путь запросов». Проверка не вызывает 1С: читает последнюю попытку cron,
текущий снимок cache_orders, применяет серверные права и фильтры, обновляет журнал.
Создание заявок и передача стоимости не запускаются.

## Развёртывание

1. Применить `migrations/115_orders_sync_diagnostics.sql` к общей БД API и cron.
   Миграция идемпотентная, не меняет заявки и бизнес-таблицы.
2. Обновить код API и cron, перезапустить соответствующие процессы.
3. Опубликовать фронтенд.
4. Дождаться `/api/cron/refresh-orders-cache` или вызвать его через установленный
   `/opt/haulz/cron-call.sh`. Для диагностики таймаута можно указать короткое окно
   `?dateFrom=YYYY-MM-DD&dateTo=YYYY-MM-DD` (не более 90 дней).
5. Выполнить проверку в песочнице и при необходимости скопировать отчёт.

Предыдущие попытки до обновления cron восстановить этой панелью нельзя.
Старый API определяется по отсутствию `orders-diagnostics-v1` в ответе.

## Как читать результат

- Нет диагностики: проверьте миграцию 115 и доступность общей БД.
- Попытки не записаны: cron ещё не выполнил новый код или пишет в другую БД.
- `request_1c`: запрос отправляется / ждёт ответа 1С, таймаут клиента — 45 секунд.
- `response_1c`: HTTP-статус получен, читается и проверяется JSON.
- `write_database`: массив прошёл проверку, выполняется сохранение.
- `database_saved` / `complete`: снимок записан.
- «Выполняется» более двух минут: возможен прерванный процесс; это предположение,
  а не подтверждение таймаута. Сверить журнал cron по request_id.
- Доступных по ИНН 0: в снимке нет заявок выбранной области доступа; проверить
  ИНН и привязку компании. Права диагностики совпадают с правами журнала.
- После названия меньше: дополнительный фильтр названия исключает записи.
- После дат меньше: записи находятся вне выбранного периода.
- API вернул больше, чем показано: проверить фильтры и поиск в приложении.

Загрузка по умолчанию охватывает последние 90 дней. Выбор «2026» в приложении
сам по себе не загружает прошлые месяцы. Для отсутствующей истории нужен backfill.
Локальные заявки, ещё не попавшие в снимок 1С, учитываются только в счётчике
приложения, поэтому он может отличаться от счётчиков cache_orders.

## Данные и ограничения

Таблица хранит только последнюю попытку: этап, время, request_id, HTTP-статус,
период, технические счётчики и безопасную категорию ошибки. Сырые ответы 1С,
пароли, заголовки авторизации и содержимое заявок не сохраняются.
Клиенту не возвращаются глобальные счётчики / содержимое чужих заказчиков.
Песочница не обходит аутентификацию и привязки компаний.
Сбой записи диагностики не останавливает основной cron.
