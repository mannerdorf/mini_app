# Автоматическая передача стоимости забора

## Условия

После миграции 119 новые сдачи на склад и изменения номера заявки/расчётов ставят забор в очередь, если:
- статус `deposited`;
- `issueCustomerBill=true`;
- `customerBillMode=auto`;
- заполнен `zayavkaNumber`.

Миграция не ставит в очередь ранее сданные заборы. Ручной расчёт остаётся с подтверждением диспетчера. Сумма, вручную изменённая в журнале, автоматически не отправляется.

Триггер и изменение забора фиксируются одной транзакцией. Обработчик берёт один забор за запуск, находит перевозку по существующему сопоставлению с проверкой ИНН, считает стоимость, повторно проверяет актуальность данных под блокировкой и вызывает `SetPickupCost`.

При нехватке данных/ошибке подготовки повтор через 15 минут. При ответе 1С статус сохраняется как `transmitted`, `manual` или `uncertain`. Записи `sending`, `transmitted`, `manual`, `uncertain`, `issued` автоматически повторно не отправляются. Авария после вызова 1С требует сверки; автоматического обещания «ровно один счёт» API 1С не предоставляет. Ошибка 401 требует проверки учётных данных.

## Развёртывание

1. Обновить код backend и cron VPS.
2. На backend с переменными окружения из `/opt/haulz/.env` применить:
   `psql "$DATABASE_URL" -X -v ON_ERROR_STOP=1 -f /opt/haulz/app/migrations/119_pickup_auto_billing.sql`
3. Перезапустить `haulz-api` на backend и `haulz-cron` на cron VPS, проверить `/health`.
4. На cron VPS добавить через `crontab -e`:

```cron
*/5 * * * * /opt/haulz/cron-call.sh /api/cron/process-pickup-auto-billing
```

5. Обновить фронтенд для актуальных подсказок.

При отсутствии очереди обработчик не делает обращений в 1С. Под нагрузкой заборы обрабатываются по одному каждые пять минут. Это фоновая передача после сдачи, а не блокирующий запрос на телефоне водителя.

## Проверка

Сдать новый автоматический забор с заполненной заявкой. Проверить очередь:

```sql
SELECT j.job_number,q.state,q.attempts,q.next_at,q.last_error,b.status,b.amount
FROM pickup_auto_billing_queue q JOIN pickup_jobs j ON j.id=q.job_id
LEFT JOIN pickup_billing b ON b.job_id=j.id ORDER BY q.updated_at DESC LIMIT 30;
```

Успех означает «Передано в 1С»; счёт далее формируется средствами 1С. Ручной забор не должен попасть в очередь. Не менять `sending`/`uncertain` на `not_issued` без сверки результата в 1С.
