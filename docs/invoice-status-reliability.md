# Надёжность статусов счетов и перевозок

## Выполнено локально

- Приоритет оплаты: корректный остаток 1С → явно указанная оплата счёта (включая ноль) → оплата связанной перевозки → текстовый статус.
- Бейдж и фильтр оплаты используют рассчитанные суммы; отмена остаётся отдельным состоянием.
- Пустой или некорректный остаток не трактуется как нулевой долг.
- Перед заменой окна счетов/перевозок проверяется известная структура списка и номера всех документов. Ошибочный ответ отклоняется до записи в БД.
- При ошибке чтения БД зарегистрированного пользователя API возвращает 503 вместо пустого успешного списка. То же правило действует при ошибке кэша в режиме cache-only.

## Ограничения

Корректный пустой список допускает очистку выбранного окна. Полноту структурно корректного ответа без признаков полноты со стороны 1С доказать нельзя. Эти изменения не исправляют пропуски старых документов в расписании.

## Следующие этапы

- Независимые очереди счетов и перевозок реализованы; включаются обновлённым deploy/crontab.haulz-cron.example.
- Обход дней с незакрытыми документами реализован; повторная сверка недавно закрытых реализована в active.
- Ночной обход истории реализован в lane=history.
- Отображение времени актуальности данных и обновление интерфейса из БД.

## Выпуск

Миграция БД и изменение API 1С не нужны. Обновить фронтенд и код обоих VPS (API и cron), перезапустить процессы. Для включения новых очередей нужно заменить расписание cron по инструкции ниже.

## Очереди обновления

`refresh-cache?kind=invoices|perevozki&lane=recent|active|history`: четыре независимых задания в `cron_work_state`.
Recent обновляет 3 дня раз в 20 минут. Active выбирает один день старых незакрытых документов за тик (5 минут), объединяет документы одной даты, сохраняет последний успешный день. После конца списка обходит его заново. Ошибка не продвигает курсор и не блокирует другой тип.

Active использует нормализованные таблицы `cache_invoices_rows` и `cache_perevozki_rows`; перед включением проверить их заполненность. Документы без даты не запрашиваются: их количество возвращается в `undatedDocuments`. Неизвестные статусы считаются открытыми. Цикл N дат занимает минимум N × 5 минут плюс задержки; возвращается `pendingDays`.

Для включения обновить оба VPS и заменить старую строку refresh-cache пятью строками из примера (не добавлять рядом со старой). Вызов без параметров оставлен совместимым со старой ротацией. Миграция не нужна при уже применённой 116. Все обращения через VPS сохраняют общий ограничитель 1С.

Active сохраняет в курсоре первое наблюдаемое закрытие по дню документов. Пока в этом дне есть открытый документ, день остаётся активным. После закрытия всех документов день проверяется не чаще раза в сутки в течение 7 дней; повторное чтение не продлевает срок. При первом включении уже закрытые дни также получают 7 дней наблюдения. Фактическая задержка зависит от длины очереди. Недавние даты обслуживает recent.

History запрашивает один день за тик, начиная с начала 90-дневного окна и заканчивая днём перед recent. Граница цикла фиксируется в курсоре; после завершения начинается новый скользящий цикл. 18 запусков за ночь на каждый тип дают полный обход примерно за 5 ночей без ошибок. Все ошибки сохраняют позицию для повтора. Существующий deep остаётся на 10 днях.

История получает приоритет 2, актуальные фоновые запросы — 1, пользовательские — 0. Общий ограничитель пропускает запросы с меньшим числом первыми.

Добавлены время сверки документов и автоопрос только БД для зарегистрированных аккаунтов. План выпуска и нерешённые серверные проверки: document-refresh-release-checklist.md.

## Старые неизвестные перевозки

После диагностики рабочей БД неизвестные/пустые статусы перевозок старше окна 90 дней вынесены в lane=archive. Отдельный курсор, общий ограничитель 1С, низкий приоритет, шесть дат за ночь. Счета и известные незавершённые перевозки любого возраста не исключаются из active. Статус архивных записей не меняется; после получения известного активного статуса они возвращаются в active. Архивная очередь не гарантирует быстрой актуализации этих записей.
